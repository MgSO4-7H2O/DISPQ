1. 系统定位

SA-WRQ 是一套面向流式向量检索的双层 ANN 框架：稳定的 main IVF/PQ 索引承载主体检索，active_delta 接收新数据，必要时通过 frozen_delta 完成无中断交接；OnlinePQ 负责轻量在线适配，balanced merge 负责把增量数据并回 main 并修复局部 IVF 分桶。

main
稳定的大规模 IVF/PQ 路由
delta
新写入与在线 PQ 适配
merge
局部重路由、重分桶、patch main
rebuild
可选的全局 whitening + main 重建兜底
最短理解：在线路径保持轻量，delta 内主要更新 PQ；当 delta 达到 rows、QE ratio、drift、delta/main ratio 或 list imbalance 条件时冻结并 merge。IVF coarse 层面的结构修复集中在 merge 的局部邻域重分桶，而不是 steady state 下单独刷新 delta coarse centroids。

运行时路由状态

系统最多同时暴露三路检索：mainfrozen_deltaactive_delta。冻结旧 delta、创建新 active delta 后，查询仍可覆盖整个可见数据集。

核心数据结构：VersionSet、VectorRecord、SearchResult、DeltaShard、SearchRoute。

CodeGraph 证据

索引状态为 up to date；CodeGraph 识别出 3 个应用入口、13 个实现模块、4 个 CTest 测试和 1 个 RSS 监控工具。关键调用链由 node 的 callers/callees trail 交叉核对。

  1. 原始 query 由 WhiteningModel::Transform 转到目标版本空间。

8. 阅读时应注意的边界

OnlinePQ ≠ coarse refresh

AddWithOnlinePQSlidingWindowImpl 更新 residual PQ 统计和 codebook；当前 steady state 不单独刷新 delta coarse centroids。

Merge 承担 IVF 修复

balanced_append 在 main centroid 邻域内重新分配并 patch partitions；它不是简单地把每条 delta 记录追加到最近 list。

两类 exact baseline

src/search/exact_search.cpp 提供公共 ExactSearchBatch；run_eval.cpp 另有面向 doc-id 路由集合的 blockwise ground-truth helper。

版本是显式状态

whitening 和 IVF 都以 VersionId 参与 route；错误 version 会通过 Status/Result 返回，而不是静默回退。

MS workload 在仓库外提供

run_eval_ms 会从 dataset 目录寻找 _workload.json，但当前源树中没有内置 workload 示例；运行时需显式提供或放置对应文件。
